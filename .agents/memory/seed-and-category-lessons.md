## Null bytes in seed questions
TypeScript string literal `\0` compiles to an actual null byte (0x00), which PostgreSQL's UTF-8 encoding rejects with `ERROR: invalid byte sequence for encoding "UTF8": 0x00`. The affected question was in the LDAP injection explanation (`Escape special characters: … \0`). Fix: spell it out as plain text rather than using the escape sequence in a TS string.

**Why:** The TS source is compiled before the string reaches pg, so the null byte is literal in the query parameter.

**How to apply:** Any seed script with literal backtick code examples — search for `\\0` or `\0` and replace with descriptive text before running.

## api-zod package resolves from source
`lib/api-zod/package.json` exports `"./src/index.ts"` directly (no compiled JS dist). The api-server uses `pnpm run build && pnpm run start`, so it compiles a bundled dist from the source at build time. After adding a new field to the zod schema, rebuild with `pnpm --filter @workspace/api-server run build` and restart the workflow, or the old binary will serve responses without the new field.

**Why:** api-server is not a tsx/ts-node watch process in dev — it compiles first.

**How to apply:** Any schema change requires a rebuild of api-server before it appears in the API response.

## api-client-react Course interface is manually maintained
`lib/api-client-react/src/generated/api.schemas.ts` is generated by orval but NOT auto-regenerated on schema changes. The `Course` interface must be kept in sync manually when fields are added to the API response. Missing fields silently return `undefined` at runtime (TypeScript types don't affect runtime behavior).

**Why:** orval codegen is not wired into a watch/build step.

**How to apply:** After adding a field to the API, also add it to the `Course` (or relevant) interface in `api-client-react/src/generated/api.schemas.ts`.

## Category grouping on home page
Courses are grouped client-side by `c.category` field, sorted by `CATEGORY_ORDER` array. The component is `CoursesByCategory` in `home.tsx`. Categories currently in use: Cloud, Languages, Frontend, Backend, Databases, DevOps, Data Engineering, Observability, Security, Infrastructure, Testing, AI & ML, APIs & Integration, Messaging, Enterprise.

**Why:** Grouping is done in the React component, not in the API, for simplicity.
